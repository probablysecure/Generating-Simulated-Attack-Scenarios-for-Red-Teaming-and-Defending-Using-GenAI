These two logs show a classic phishing to command execution attack chain. It starts with the phishing email sent to the victim with a malicious macro-enabled attachment. Once the victim clicks on the attachment, it performs code execution that allows the reverse shell to execute commands on the victims machine and allow remote system access. 

This is a highly critical issue as the attackers can access sensitive hospital through the files, steal login credentials, modify or delete data. In a hospital setting, the data can be patient data as well.

## Section 8: Final Recommendations

My final recommendations include blocking macro-enabled documents, blocking ports, use of AI for detection, and staff training on phishing. 

Macro-enabled documents contain embedded code that run when the document is opened. By blocking these documents, it prevent the code from running when the document is opened. Another fail safe is to unnecessary open ports, like port 4444. This port can be used as reverse shell connector, meaning it calls back to the attacker machine allowing it in for remote access. The use of AI agents can be very helpful in quickly detecting attacks and notifying defense teams. Regular training for staff members about phishing can help lower attacks altogether. Giving staff members the tools to identify phishing and other suspicious emails allows them to do their part in preventing these attacks from transpiring.
